# 部署指南 · 日迹

> 从「本地能跑」到「别人能在微信里搜到」，一共四个阶段。
> 微信平台规则会变，凡涉及具体入口路径与资质要求的，**以官方最新页面为准**。

---

## 先选路线

| 路线 | 你能得到 | 需要什么 | 耗时 |
|---|---|---|---|
| **A. 本地自用** | 只在开发者工具 + 自己手机上看得到 | 无（测试号即可） | 10 分钟，已完成 |
| **B. 体验版** | 自己和最多十几位朋友能长期用 | 注册小程序拿正式 AppID | 半天 |
| **C. 正式上线** | 微信里能搜到、任何人可用 | B + 提交审核通过 | 1-3 天（审核时长不定） |

**云同步是独立开关**，任何路线都可以选择开或不开，不影响能否部署。

---

## 路线 A：本地自用（已可执行）

1. 微信开发者工具 → 导入项目 → 选 `日迹-life-log/` 目录
2. AppID 处点「测试号」（`project.config.json` 里就是 `touristappid`）
3. 编译 → 模拟器里就能用
4. 想在手机上用：点工具栏「预览」→ 手机微信扫码 → 打开的是**临时预览版**

**局限**：预览版关掉就没了，且测试号**不能开通云开发**、不能上传版本。适合"先记几天看顺不顺手"。

---

## 路线 B：体验版（推荐先走这条）

### B1. 注册小程序账号，拿 AppID

1. 打开 https://mp.weixin.qq.com → 立即注册 → 选「小程序」
2. 需要准备：
   - **一个没注册过公众号/小程序的邮箱**（这是最常见的卡点，用过的邮箱不行）
   - 身份证信息 + 本人微信扫码验证
   - 手机号
3. 注册完成后：后台左侧「设置 → 基本设置」里能看到 **AppID**，复制它
4. 同一个身份证最多注册 5 个小程序；个人主体**不能**开通微信支付

> 名称「日迹」若已被占用，后台会提示，换个名字即可。名称可后续修改（一年有限次）。

### B2. 把 AppID 填进项目

两种方式，任选：

- **方式一（推荐）**：开发者工具 → 右上角「详情」→「基本信息」→ AppID 改成你的 → 工具会写入 `project.private.config.json`（该文件已被 `.gitignore` 忽略，不会污染仓库）
- **方式二**：直接改 `project.config.json` 的 `"appid"` 字段（会提交到仓库，仓库公开时 AppID 可见——AppID 不是密钥，风险很低）

### ⚠️ 换 AppID 会读不到旧数据

`wx.setStorageSync` 的数据是**按 AppID 隔离**的。测试号 `touristappid` 下记的记录，换成正式 AppID 后一条都看不到。

**所以：如果测试期间记了真实数据，切换前必须先备份。**

目前程序只有「导出到剪贴板」，**没有导入功能**——导出的 JSON 切完 AppID 后没法灌回去。两个选择：

- 简单办法：正式上线前只记测试数据，别记真的
- 或者告诉我，我给「我的」页加一个「从剪贴板导入 JSON」的按钮（约半小时）

### B3. 上传体验版

1. 开发者工具 → 右上角「上传」→ 填版本号（如 `0.2.0`）和项目备注
2. 小程序后台 →「管理 → 版本管理」→ 找到刚上传的开发版本 → 点「选为体验版」
3. 同一页「成员管理」→ 添加体验成员（微信号），他们扫码就能用
4. 体验版**不会过期**，适合长期自用，也适合让朋友试

**体验版不需要审核**，但只有体验成员能用，微信里搜不到。

## 云开发部署（可选，体验版就能用）

**不开云同步也完全能用**，数据存本地。开了之后换手机能同步、删小程序不丢数据。

前提：必须是**正式 AppID**（测试号开不了云开发）。

1. 开发者工具顶部工具栏点「云开发」→ 开通 → 创建环境（名字随意，如 `life-log-prod`）→ 记下**环境 ID**（形如 `life-log-3gk2xxxxxx`）
2. 云开发控制台 →「数据库」→ 创建集合 **`records`**，权限保持默认「仅创建者可读写」
3. 同一页「索引管理」→ 添加索引：`openid` 升序 + `updatedAt` 升序（两个字段，复合索引）
4. 回到开发者工具，左侧文件树找到 `cloudfunctions/records` → **右键 →「上传并部署：云端安装依赖」**
5. 等部署完成（控制台出现 `records` 函数、状态正常）
6. 打开小程序 →「我的 → 云同步」→ 填环境 ID → 打开开关

首次开启会把历史记录全量推上云，底部会提示推送条数。

**验证**：云开发控制台 → 数据库 → `records` 集合里应该能看到你的记录，每条带 `_openid`。

**费用**：有免费额度，超出按量计费。个人日均几十条记录的量级，正常不会超。以官方资费页为准。

## 路线 C：提交审核、发布

### C1. 提审前必须配的

| 项 | 位置 | 说明 |
|---|---|---|
| 服务类目 | 后台「设置 → 基本设置 → 服务类目」 | 选 **工具 → 效率/办公**。个人主体可选，无需资质。**不要**选金融、医疗健康类，会要求资质 |
| 用户隐私保护指引 | 后台「设置 → 服务内容声明 → 用户隐私保护指引」 | 本项目不调用任何隐私接口，选「不收集任何用户信息」即可，但**必须填**，不填无法提审 |
| 服务器域名 | 后台「开发 → 开发管理 → 服务器域名」 | 本项目不用外部请求，**留空**。开了云开发也不需要配（走微信内部通道） |

### C2. 上传并提交

1. 开发者工具「上传」→ 版本号 `1.0.0`，备注写清更新内容
2. 后台「版本管理」→ 开发版本 →「提交审核」
3. 审核表单：
   - 功能页面：勾选全部 5 个页面
   - 测试账号：本项目无需登录，选「无需登录」
   - 补充说明：写一句「个人生活记录工具，所有数据仅存于用户手机本地/用户自己的云开发环境，不涉及交易、不收集个人信息」
4. 审核通常几小时到几天，被驳回会说明原因，改完重新提交

### C3. 发布

审核通过 → 后台「版本管理」→「发布」→ 全量发布。之后微信里搜名称就能找到。

## 提审 checklist（本项目逐条对照）

- [x] 无支付、无资金归集、无多人分账
- [x] 体重/睡眠只做记录与数字展示，**不输出**「你超重了」「建议就医」这类健康判断
- [x] 饮酒模块无酒类商品推荐、购买链接、品牌推广
- [x] 不调用隐私接口（无定位、无手机号、无通讯录）
- [ ] 服务类目已选「工具 → 效率」
- [ ] 用户隐私保护指引已填写
- [ ] 每个页面都有空状态，无白屏（首页空状态目前只有一行字，偏简陋，可接受）
- [ ] tabBar 目前是**纯文字**（`iconPath` 为空）。能过审，但建议补图标，观感差别很大

## 常见驳回原因（按本项目风险排序）

| 驳回理由 | 触发点 | 怎么改 |
|---|---|---|
| 类目与功能不符 | 选了金融/医疗健康类 | 改回「工具 → 效率」 |
| 提供了健康建议 | 体重页出现"偏胖""注意饮食"之类文案 | 只保留数字，删除所有评价性文案 |
| 涉及酒类经营 | 出现购买入口、品牌名 | 只记录「啤酒/红酒」这类品类，不出现商品 |
| 未填隐私保护指引 | 后台漏填 | 补填 |
| 功能不完整/白屏 | 首启无引导、无数据时页面空 | 已有空状态，若被驳则补首启引导 |
| 诱导分享 | 分享得奖励 | 本项目无分享功能 |

## 一张图记住顺序

```
本地跑通(测试号)
   ↓
注册小程序 → 拿 AppID → 填进项目
   ↓                    ↘
(可选)开通云开发 → 部署云函数 → 填环境ID开同步
   ↓
上传 → 设为体验版 → 自己和朋友用
   ↓
提交审核 → 通过 → 发布 → 微信里可搜
```

## 当前唯一的技术债

**没有 JSON 导入功能**——换 AppID 会导致旧数据读不到，且导出的 JSON 无法灌回。在正式记数据前建议补上（半小时的活）。
