# 需求台账

> 机制：每个需求先在这里登记编号 → 写设计文档（`docs/需求/REQ-XXX-*.md`）→ 评审通过后才开工 → 交付后回填落点版本。
> 状态：待评审 / 设计中 / 开发中 / 已交付 / 已搁置
> 约定：一个需求对应一个可独立说清的功能闭环；范围变更（砍/加）必须回写该需求的设计文档，不留口头约定。
