# REQ-002 · 浇水 / 晒太阳到期提醒

> 状态：已搁置（v0.3.0 评审时决定从 REQ-001 拆出，暂缓实施）
> 登记日期：2026-10-20
> 前置：REQ-001 已交付（植物档案与养护方案已就位）

---

## 一、需求描述

按每盆植物自己的周期，提醒主人该浇水了、该挪出去晒太阳了。

## 二、为什么暂缓

微信的硬约束决定了「定时提醒」的上限：

- **订阅消息是一次性的**：用户每授权一次只能发一条，额度用完即止
- **长期订阅模板不对个人主体开放**
- 模板须在小程序后台从公共模板库选用，个人主体可用模板有限，能否批下来不确定

因此提醒的价值大头在「打开小程序就能看到」，而这依赖 REQ-001 的档案先跑起来积累使用习惯，不急于第一版。

## 三、设计备忘（重启时直接用）

### 提醒三层

| 层 | 能力 | 依赖 |
|---|---|---|
| L1 | 到期计算：`下次日期 = lastWateredAt + care.waterDays` | 纯本地 |
| L2 | 打开即见：首页横幅「N 盆待浇水」、列表标红、详情待办条 | 纯本地 |
| L3 | 订阅消息推送：云函数定时触发器（每日 9:00）扫描到期植物按 openid 聚合下发 | 模板 ID + 订阅额度，无额度静默跳过 |

任何一层缺席不影响上层；L3 是增益不是前提。

### 数据预留（REQ-001 已埋）

- `care.waterDays` 已存在于档案（AI/知识库都会给值）
- 启动时需增量补：`lastWateredAt`、`lastSunAt`、`care.sunDays`（0 = 忌直射不提醒）、`reminder: {water, sun}`（单盆开关）

### 打卡闭环

浇水/晒太阳打卡 → 更新档案日期 + 写一条 `type: 'plant'` 的 record（进首页卡片/流水/统计，注册表自动适配）→ 重算下次到期日。

### 到期等级

```
剩余天数 d = 下次日期 - 今天
d > 1   ok       「还有 N 天浇水」
d = 1   soon     「明天该浇水」
d = 0   due      「今天该浇水」
d < 0   overdue  「逾期 N 天未浇水」
未记录   never    「未记录浇水」
```

### 部署增量

- 新云函数 `plantReminder` + 定时触发器
- 环境变量 `PLANT_TEMPLATE_ID`
- 打卡时顺手 `wx.requestSubscribeMessage` 攒额度（需在隐私指引声明）

## 四、重启条件

REQ-001 用满两周、确认档案数据结构稳定（无字段迁移需求）后，从「L1 + L2」做起；L3 视模板申请结果决定。
