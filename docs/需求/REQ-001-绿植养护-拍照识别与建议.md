# REQ-001 · 绿植养护 —— 拍照注册与养护建议

> 状态：已交付（v0.3.0，53 项单测全绿）
> 登记日期：2026-10-20 · 交付日期：2026-10-20
> 关联：REQ-002（到期提醒，本版不做，见其文档「数据预留」一节）

---

## 一、需求描述

在小程序里管理家里的绿植：

1. **拍照注册** —— 拍一张照片即可建一盆植物的档案，照片、品种自动带入
2. **识别解析** —— 由多模态模型解析照片：品种、置信度、健康状态、当前存在的问题
3. **养护建议** —— 每盆一份方案：光照、浇水、温度、湿度、施肥、土壤、毒性提示，外加针对照片的诊断结论

**明确不在本版**（防止范围蔓延）：浇水/晒太阳打卡与到期提醒（REQ-002）、订阅消息推送、品种百科、商城类目。

## 二、关键决策记录（评审结论）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 模型默认**智谱 GLM-4V-Flash**（免费档），云函数内留阿里 qwen-vl 适配 | 免费可用；两家同为 OpenAI 兼容协议，切换只改环境变量 |
| D2 | 植物档案**独立存储**（`life_log_plants_v1`），不塞进 records 流水 | 植物是有照片、有方案的长期实体，与「发生了一件事」的流水模型不同构 |
| D3 | API Key 只存**云函数环境变量**，客户端零密钥 | 小程序包可被解包 |
| D4 | 无云开发 / 无 Key / 识别失败时**降级为手选品种**（内置 24 种知识库），档案照建 | 延续项目「不配云端也能跑」的基因；AI 是升级项不是门槛 |
| D5 | 页面两个：绿植列表 + 绿植详情；入口放「我的」页，不动 tabBar | 最小可用；tabBar 位置宝贵 |
| D6 | 识别结果先确认再建档（弹窗显示品种与置信度，可改选手选） | 模型会认错，让用户把关 |
| D7 | 详情页支持**改品种**：改完从知识库重算方案 | 兜 D1 的识别误差 |
| D8 | 解析与归一化全部写成**纯函数**，配 Node 单测 | TDD；模型返回是脏数据重灾区 |

## 三、链路设计

```
wx.chooseMedia（相机/相册）
  → wx.compressImage（quality 70，失败用原图）
  → 有云环境：wx.cloud.uploadFile 拿 fileID
              → 云函数 plantAI：downloadFile → base64 → 多模态模型 → 结构化 JSON
  → 无云环境：跳过识别
  → wx.saveFile 存本地持久副本（离线也能看照片）
  → 用户确认品种（AI 结果 / 手动选）
  → 建档落 life_log_plants_v1 → 跳详情
```

失败分支：云函数报错 / Key 未配 / 模型超时 → toast「识别失败，手动选个品种吧」→ 走手选，`source: 'library'`。**任何失败都不阻断建档。**

## 四、数据模型

存储 key：`life_log_plants_v1`（数组，软删除，与 records 同款纪律）。

```js
{
  id: 'p' + 时间基36 + 随机,     // 档案主键
  name: '窗台那盆',               // 用户命名，默认 = 品种名
  species: '绿萝',                // 品种（AI 识别或手选）
  speciesKey: 'pothos',           // 命中知识库的键，未命中为 ''
  photo: {
    fileID: 'cloud://...',        // 云存储地址（有云时）
    localPath: 'wxfile://...'     // 本地持久副本（兜底显示）
  },
  care: {                         // 养护方案，字段可空，页面按空跳过
    light: '', water: '', waterDays: 0,   // waterDays 供 REQ-002 复用
    temp: '', humidity: '', fertilizer: '', soil: '', toxicity: ''
  },
  health: '健康',                 // 健康 / 一般 / 需关注
  issues: [{ title: '', detail: '' }],    // 针对本次照片的诊断
  tips: [],                       // 模型给的补充建议
  confidence: 0.86,               // 识别置信度，手选为 0
  source: 'ai',                   // ai | library | manual
  createdAt: 0, updatedAt: 0,
  deleted: false
}
```

## 五、云函数 plantAI

```
入参 { action: 'analyze', fileID }
出参 { code: 0, data: {species, confidence, health, care, issues, tips}, provider, model }
     { code: 4xx/5xx, message }
```

- 体积守卫：base64 后 > 4MB 返回 413（提示重拍）
- 环境变量：`AI_PROVIDER`（zhipu 默认 / dashscope）、`AI_API_KEY`（必填）、`AI_MODEL`（可选）
- 输出约束：system prompt 给字段字典并要求只返回 JSON；解析层剥 markdown 围栏、截首尾大括号、支持 `{analysis:{...}}` 包裹
- 归一化：数值夹取（confidence 0~1、waterDays 1~60）、issues 字符串数组转对象、health 枚举兜底
- 无第三方依赖（`wx-server-sdk` + Node 内置 `https`），云端安装快

## 六、本地知识库（utils/plantCare.js）

24 种常见室内植物：名称、别名（含拉丁名/俗名）、光照、浇水、周期、温度、湿度、施肥、土壤、毒性。

职责：
1. 手选品种时的完整方案来源（`source: 'library'`）
2. AI 方案的字段补缺与数值夹取（AI 常漏结构化字段）

## 七、页面

| 页面 | 路径 | 内容 |
|---|---|---|
| 我的绿植 | `pages/plants/index` | 档案卡片列表（照片、名字、品种、健康状态）、拍照按钮、手动添加、长按删除、空态引导 |
| 绿植详情 | `pages/plant-detail/index` | 大图、名字/品种/置信度/来源、养护七项、当前问题、小贴士、改品种、改名、删除 |

入口：「我的」页新增「我的绿植」行。

## 八、验收标准

1. `node tests/run.js` 全绿（知识库 / 解析归一化 / 档案服务三组）
2. 无云环境：拍照 → 手选 → 建档 → 详情完整展示知识库方案
3. 有云环境（部署 plantAI + 配 Key 后）：拍照 → 识别 → 确认 → 建档；识别失败自动落手选
4. 建档后杀掉小程序重进，照片仍可显示（本地副本兜底）
5. `node --check` 全部 JS 通过；README / 设计方案 / 项目档案三处同步更新

## 九、部署步骤（用户侧）

1. 开发者工具右键 `cloudfunctions/plantAI` → 上传并部署：云端安装依赖
2. 云开发控制台 → 云函数 plantAI → 配置 → 环境变量：`AI_PROVIDER=zhipu`、`AI_API_KEY=<开放平台的 Key>`
3. （可选）`AI_MODEL` 覆盖默认模型
4. 小程序后台 → 设置 → 用户隐私保护指引：声明「摄像头」「相册（仅写入）」，用途写「拍摄绿植照片用于识别品种与生成养护建议」

**基础库要求**：改名/自定义品种用的 `wx.showModal({ editable: true })` 需基础库 ≥ 2.17.1（2021 年版本，覆盖面足够）；真机若表现异常优先核对基础库版本。

## 十、合规

- 植物养护建议不涉及人体健康，不触碰「体重/睡眠不得输出健康建议」的提审红线
- 知识库与模型提示词中不出现「治病」「药用」「可食用」表述；毒性字段只写「避免误食」
- 照片仅用于识别，传至本人云开发环境与模型厂商，隐私指引需声明
